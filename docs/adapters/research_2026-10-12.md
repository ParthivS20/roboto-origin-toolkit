# DM-USB2FDCAN adapter protocol and firmware

Research date: 2026-10-12. Device observed: VID 34B7, PID 6877, single-channel DM-USB2FDCAN; original reported firmware app v1.0.0.5.

## Factory communication protocol

The manufacturer explicitly says the module's low-level protocol is not public and directs developers to its SDK:
https://github.com/dmBots/dm-tools/blob/master/USB2CANFD/SETUP.md

Module manual (includes adapter upgrade instructions):
https://github.com/dmBots/dm-tools/tree/master/USB2CANFD

The community python-can-damiao plugin implements a serial binary protocol. Its presence alone does not prove compatibility with this adapter's installed firmware. The vendor warns that older SDKs are incompatible with newer firmware starting at single-channel version 1004:
https://github.com/dmBots/dm-tools/blob/master/USB2CANFD/SDK/UPDATE.md

## Official alternative firmware exists

The same vendor repository supplies single-channel gs_usb and SLCAN packages, as well as factory firmware. Do not substitute packages from USB2CANFD_Dual, CANable, or unrelated STM32 boards.

- gs_usb 1.0.0.3: native Linux SocketCAN route; verify board revision compatibility and post-flash enumeration. This is the preferred candidate for avoiding serial bridges, but hardware compatibility has not been proven by flashing.
- SLCAN 1.0.0.2: vendor documents Linux slcand setup and switching back to factory firmware.
- Factory 1.0.0.6: current package listed in the repository.
- Factory 1.0.0.5: historical package matching the version read from this adapter; retained as a recovery candidate, not a dump of the installed device's full memory or bootloader.

## Vendor flashing process

Official SLCAN instructions:
https://github.com/dmBots/dm-tools/blob/master/USB2CANFD/固件/socketcan/slcan固件/FLASHING.md

The module manual says:
1. Open the matching vendor host application and connect to the adapter.
2. Press F9 to open the **adapter firmware upgrade** window.
3. Select the correct adapter .enc firmware package, then upgrade.
4. Wait for successful completion and automatic restart; read the adapter version afterward.

Use the adapter upgrade window, not the ordinary motor firmware upgrade controls. The vendor says factory and SLCAN firmware can be switched by reflashing. Confirm the exact hardware revision and that the installed host application supports the appropriate upgrade flow before writing. Firmware replacement can change the device protocol, VID/PID and behavior; preserve recovery files and keep the motor disconnected during adapter flashing.

A separate vendor USB2CANFD-series upgrader is also listed:
https://github.com/dmBots/dm-tools/tree/master/USB2CANFD通用升级工具
Its macOS compatibility has not been established here.

## Important vendor-specific SLCAN bitrate mapping

This firmware does not use the conventional SLCAN bitrate indices:

| Command | Bitrate | Format |
|---|---|---|
| S0 | 100 kbps | CAN |
| S1 | 125 kbps | CAN |
| S2 | 200 kbps | CAN |
| S3 | 250 kbps | CAN |
| S4 | 500 kbps | CAN |
| **S5** | **1 Mbps** | **CAN** |
| S6 | 2 Mbps | CAN FD |
| S7 | 4 Mbps | CAN FD |
| S8 | 5 Mbps | CAN FD |

After installing that firmware, the 1 Mbps Linux setup would be (substitute the observed serial port):

```sh
sudo slcand -o -c -s5 /dev/ttyACM0 slcan0
sudo ip link set slcan0 up
candump slcan0
```

Run the receive monitor first, then in another terminal send a read-only firmware request for motor 18:

```sh
cansend slcan0 7FF#1200330E
```

Expected confirmed DMTool reply: CAN 022, data `12 00 33 0E 36 31 31 37` (firmware 6.1.1.7). These post-flash steps have not been run on this adapter. The Pi's pre-existing can0 belongs to its onboard SPI CAN controller, not this USB adapter.
